Queue worker migration plan

The current workers poll Redis every 500 ms. Moving to blocking pops removes the idle load and cuts median pickup latency. This plan covers the rollout order and the rollback path.

Rollout order

  • Ship the new consumer behind WORKER_BLOCKING_POP, off by default.
  • Enable it on the email queue first; it has the lowest volume.
  • Watch pickup latency for 24 hours, then enable the remaining queues.

Consumer loop

for {
    job, err := q.BlockingPop(ctx, "jobs:email", 5*time.Second)
    if errors.Is(err, queue.ErrTimeout) {
        continue // no work; loop again
    }
    handle(ctx, job)
}

Expected effect

email250 ms4 ms
webhooks260 ms5 ms
reports245 ms4 ms

Rollback is a flag flip. See the runbook for the alert thresholds.
